# 本番を公開したときの確認（スモークテスト）

本番の API（Cloud Run）ができたとき（[DEPLOY_API.md](DEPLOY_API.md) の手順7の後）と、大きな変更を main に入れたときに、上から順に確かめます。所要時間は30分ほどです。#14 の完了条件との対応は、最後の表にまとめました。

> パスワード・トークン・リンクは、チャット・Issue・PR に貼らないでください。結果を Issue に書くときは「OK」「失敗：〜」だけにします。

## 1. 外からの自動確認（スクリプト）

ログインせずに確かめられる点を、`scripts/smoke-test.sh` でまとめて確かめます。Git Bash（Windows）か Cloud Shell で、リポジトリのルートから実行します。

```bash
CLOUD_RUN_URL=https://yamon-api-xxxx.asia-southeast1.run.app bash scripts/smoke-test.sh
```

`CLOUD_RUN_URL` には、CI の Summary に出た Cloud Run の URL を入れます（URL は秘密ではありませんが、リポジトリには書きません）。省くと、Cloud Run への直接のアクセスの確認だけを飛ばします。

| 確かめること | 期待する結果 | 失敗したときに見る所 |
|---|---|---|
| トップ・画面のパスの直接アクセス | 200 の HTML（D42） | GitHub Actions の `Deploy (Cloudflare Workers)` |
| Worker 経由の `/api/health` | 200 `{"status":"ok"}`（初回は0台からの起動で数秒） | 503 `api_unavailable` なら Worker の Secret、403 なら `PROXY_SECRET` の食い違い（DEPLOY_API.md の「困ったとき」） |
| セキュリティ用のヘッダー | `x-content-type-options: nosniff` | Cloud Run のログ |
| 未ログインの `/api/records` | 401 | Cloud Run のログ |
| JSON 以外の POST | 415（CSRF 対策、D33） | Cloud Run のログ |
| ない API | JSON の 404 | — |
| `/api/setup` | 済んでいれば OK、まだなら警告（2で登録する） | 「SETUP_TOKEN がない」なら Secret Manager の `yamon-setup-token` |
| 地図データ | 参照先の JSON と Range の 206。R2 がまだなら警告（#25） | [MAP_DATA.md](MAP_DATA.md) |
| Cloud Run への直接のアクセス | ヘッダーなし・違う値とも 403（D44） | 200 なら Cloud Run に `PROXY_SECRET` が渡っていない（`ci.yml` の `--set-secrets`） |

ほかの使い方：

- PR のプレビュー：`bash scripts/smoke-test.sh https://pr-<番号>-yamon-site.yamonken.workers.dev --preview`（API につながらず 503 になることを確かめる、D45）
- 手元の開発環境：`npm run dev` の後に `bash scripts/smoke-test.sh http://localhost:5173 --no-map`（地図データを手元に置いていなければ `--no-map`）

失敗が1つでもあれば、終わりに「失敗 N件」と出て、終了コードが 1 になります。

## 2. 画面での確認（チェックリスト）

パソコンのブラウザで、https://yamon-site.yamonken.workers.dev を開いて行います。招待した部員の役割は、確認が済んだら直すか退会処理をします。

### 2-1. 初回セットアップと最初の管理者

- [ ] `/login` を開くと `/setup` に移る（ユーザーが0人のとき、D38）
- [ ] `yamon-setup-token`（[DEPLOY_API.md](DEPLOY_API.md) の手順4で表示された値）と、名前・メールアドレス・パスワードを入れて登録すると、管理者画面に移る
- [ ] 一度ログアウトし、同じメールアドレスとパスワードでログインできる
- [ ] もう一度 `/setup` を開いても、ログイン画面に戻る（セットアップは1回だけ）

### 2-2. 主な場所の初期データ

幹部から届いた一覧（CSV：`名前,緯度,経度`）を本番の DB に入れます（D37）。一覧がまだなら、管理者画面の「主な場所」から手で足すか、後に回します。

1. 本番の DB の接続文字列（Neon）を、そのときだけ環境変数に入れる。大学などのネットワークで 5432 番につながらないときは、Cloud Shell（リポジトリを clone して `npm ci`）で行う

   ```bash
   read -rs DATABASE_URL && export DATABASE_URL
   ```

2. 確認だけ（DB は変わらない）。追加される場所の一覧が出る

   ```bash
   npm run db:import-locations -w @yamon/api -- 一覧.csv
   ```

3. 一覧が正しければ、実際に入れる

   ```bash
   npm run db:import-locations -w @yamon/api -- 一覧.csv --apply
   ```

4. 終わったら `unset DATABASE_URL` で消す

- [ ] 管理者画面の「主な場所」と、ホームの記録フォームの場所の選択肢に、入れた場所が出る

### 2-3. 招待リンクと登録（D46）

- [ ] 管理者画面で、自分の別のメールアドレス（または協力してくれる部員）宛てに、役割「部員」で招待を作ると、招待リンクとコピーのボタンが出る
- [ ] 別のブラウザ（シークレットウィンドウ）でリンクを開き、名前とパスワードを設定して登録すると、ホームに移る。登録画面に個人情報の扱いが出ている
- [ ] 同じリンクをもう一度開くと、使えない（1回限り）
- [ ] 管理者画面の部員の一覧に、登録した人が出る。操作履歴に招待と登録が残る

### 2-4. 記録・観察会（部員で操作する）

- [ ] ホームで記録を追加する（生き物を検索して選ぶ・その場で新しい生き物を登録する、場所は「主な場所」「その他の場所」「場所を指定しない」をそれぞれ1回）
- [ ] 自分の記録を編集・削除できる。管理者の記録には編集・削除のボタンが出ない
- [ ] 観察会一覧で観察会を作り、観察会詳細から記録を追加・編集・削除できる
- [ ] 観察会を編集・削除できる（削除しても記録は「観察会なし」で残る、D40）
- [ ] 再読み込み・別の端末でログインしても、同じ記録が見える（データが DB に入っている）

### 2-5. マップ・場所別

- [ ] マップに、座標のある記録のピンが出る。同じ地点はまとまる。生き物・月・時間帯で絞り込める

- [ ] 場所別に、主な場所ごとの生き物と観察回数が出る

### 2-6. スマホの実機で GPS（#14 の完了条件）

### 2-7. 権限（管理者画面で役割を変えて確かめる）

## 3. 失敗したときに見る所

| 何が起きたか | 見る所 |
|---|---|
| CI が失敗した | GitHub の「Actions」→ 失敗した実行 → 失敗したジョブのログ。Summary に URL やイメージ名が出る |
| API が 500 を返す・遅い | Google Cloud の「Cloud Run」→ `yamon-api` →「ログ」（エラーはスタックトレースごと出る）。「指標」でインスタンス数・起動時間 |
| 画面が出ない・`/api/*` が 503・403 | Cloudflare の「Workers & Pages」→ `yamon-site` →「Logs」（Live ログ）と「Settings」→「Variables and Secrets」 |
| DB に入っていない・つながらない | Neon のダッシュボード（「Monitoring」の接続数、「Tables」で中身）。止まっていても、最初のアクセスで数秒で起きる |
| 地図データが出ない | [MAP_DATA.md](MAP_DATA.md)、Cloudflare の R2 のバケット |
| 前の状態に戻したい | DEPLOY_API.md の「前の版に戻す」（Cloud Run のリビジョン）と、Cloudflare の「Deployments」 |
