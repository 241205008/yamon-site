# MVP（合意版）

フロントエンド・バックエンド分離版の MVP。2026-10-13 にユーザーと合意し（[Issue #6](https://github.com/241205008/yamon-site/issues/6)）、2026-10-15 と 2026-10-16 にサークルの回答を受けて更新した（[Issue #22](https://github.com/241205008/yamon-site/issues/22)・[Issue #33](https://github.com/241205008/yamon-site/issues/33)）。
デザイン（Figma Make の7画面）と初期の仕様書 SPEC.md（リポジトリ外）を土台にし、食い違う場合はここに書いた内容を優先する。

## 1. 前提

- 自然観察会の参加者が、見つけた生き物を記録・共有する Web アプリ
- 運営は大学のサークルへ委託する。保守（不具合の修正・更新）は開発者が担当する（サークル内に担当できる人がいないため）
- 利用者は部員と OB・OG。招待制。約100人（300人程度まで増えても無料で動く構成にする）。10年以上使い続ける
- 管理者は代表と副代表の2人体制
- バックエンドを作る目的は次の3つ
  - 端末やメンバーの間でデータを共有する
  - サーバー側で認証・権限を検証する
  - 容量を気にせず記録を貯め続ける
- 費用は無料枠の範囲に収める（サークルの予算の目安は年1,000円程度）。Google Cloud のカードは開発者のものを登録する
- 利用する端末：iPhone・Android（スマホ、観察会の現場）、Windows・Mac（パソコン）。全画面をレスポンシブ対応にする
- 観察と地図の範囲は**愛知・岐阜・三重・滋賀の4県**
- **完成の目標：2026-10-21（水）**

## 2. 役割と権限

### 役割

| 役割 | 想定する人 |
|---|---|
| 管理者 | 代表・副代表。複数人を置ける |
| 幹部 | サークルの幹部 |
| 部員 | 一般の部員 |
| OB・OG | 卒業した人。記録を見ることだけできる（閲覧のみ） |

役割とできることの対応は1か所（`packages/shared`）で定義し、役割を後から足せるようにする。

### できること

| 操作 | 未ログイン | OB・OG | 部員 | 幹部 | 管理者 |
|---|---|---|---|---|---|
| ログイン、招待リンクからの登録、パスワード再設定 | ○ | — | — | — | — |
| 記録・観察会・地図・場所別一覧を見る | × | ○ | ○ | ○ | ○ |
| 保護対象の生き物の正確な位置を見る（下記） | × | ×（ぼかした位置。自分の過去の記録は正確な位置） | ×（ぼかした位置。自分の記録は正確な位置） | ○ | ○ |
| 記録を追加する | × | × | ○ | ○ | ○ |
| 記録を編集・削除する | × | ×（自分の過去の記録も不可） | 自分の記録のみ | 自分の記録のみ | 自分の記録のみ |

| 地図データを更新する | × | × | × | × | ○ |

権限はすべてサーバー側で検証する。画面でボタンを隠すだけにしない。

### 保護対象の生き物の位置

- 保護の対象は、**各県（愛知・岐阜・三重・滋賀）のレッドデータブックに絶滅危惧種として載っている生き物**。管理者・幹部が、生き物ごとに「位置を保護する」印を付ける
- 印の付いた生き物の記録は、部員と OB・OG には約1km単位に丸めた位置を返す。地図のピンもその位置に立つ。**記録した本人（OB・OG になった人を含む）には正確な位置を返す**
- 丸める処理は API 側で行い、正確な座標をブラウザに送らない
- 保護対象の生き物は、**場所を登録せずに記録できる**（記録フォームの「場所を指定しない」を選べる。保護対象の生き物を選んだときは、この選択肢があることを画面で案内する）

### 管理者

- 管理者は、他のユーザーの役割を「管理者／幹部／部員／OB・OG」に変更できる
- 最後の1人の管理者は、降格・無効化・退会させられない（管理者がいなくなるのを防ぐ）
- 役割の変更・無効化・退会処理は、誰がいつ行ったかを操作履歴に残す

### アカウントの状態

| 状態 | ログイン | 閲覧 | 記録の追加・編集 | 記録者の表示 | 名前・メールアドレス | 元に戻せるか |
|---|---|---|---|---|---|---|
| 通常（管理者／幹部／部員） | ○ | ○ | ○ | 本人の名前 | 残す | — |
| OB・OG（役割） | ○ | ○ | × | **「OB/OG」** | 残す（ログインに必要） | ○ 管理者が役割を戻せる |
| 無効化（一時停止） | × | × | × | 本人の名前 | 残す | ○ |
| 退会（匿名化） | × | × | × | 「退会済みユーザー」 | 名前とメールアドレスを削除 | × 戻せない |

- 典型的な流れ：部員 →（卒業）→ OB・OG →（本人の希望など）→ 退会
- OB・OG や退会した人が卒業前・退会前に登録した記録は、すべて残す

### ログイン

- ログインしたままでいられるのは**最大8時間**。それを過ぎたらログインし直す
- パスワード再設定リンクの有効期限は**1時間**（1回限り）
- 招待リンクの有効期限は48時間（1回限り）

## 3. 画面と機能

| 画面 | 機能 |
|---|---|
| 初回セットアップ | ユーザーが1人もいないときだけ表示。最初の管理者（名前・メールアドレス・パスワード）を登録する。登録には、デプロイした人だけが知っているセットアップ用トークン（サーバーの環境変数）の入力を必須にし、公開直後に第三者が管理者になるのを防ぐ（[#4](https://github.com/241205008/yamon-site/issues/4)） |
| ログイン `/login` | メールアドレス＋パスワードでログイン。招待リンクから名前とパスワードを設定して登録。パスワードを忘れたら、管理者が発行した再設定リンクで再設定する（メールの設定があれば「パスワードを忘れた方」から自分で申請もできる。[#5](https://github.com/241205008/yamon-site/issues/5)・D46）。登録画面に個人情報の扱い（4章）を表示する |
| ホーム `/` | 観察記録の追加・編集・削除（生き物の検索選択・その場での新規登録、場所＝主な場所／その他／指定しない、地図クリックや GPS での座標、日時、メモ）。最近の記録10件。観察会の作成（3ステップ）。生き物管理。OB・OG には追加・編集の操作を出さない |
| マップ `/map` | 座標のある記録をピン表示し、同じ地点はまとめる。生き物・月・時間帯で絞り込み。地図は4県の範囲だけ表示し、国土地理院の航空写真に切り替えられる |
| 場所別 `/locations` | 主な場所ごとに、見られた生き物と観察回数 |
| 観察会一覧 `/event-list` | 統計と観察会の一覧 |
| 観察会詳細 `/event-detail/:id` | 観察会内の記録の追加・編集・削除。観察会の編集・削除（[#7](https://github.com/241205008/yamon-site/issues/7)） |
| 管理者 `/admin` | 招待リンクの作成・作り直し・取り消し、パスワード再設定のリンクの発行、役割の変更、無効化・有効化、退会処理、操作履歴、統計、主な場所の管理、地図データの更新 |

### 観察会の編集・削除（[#7](https://github.com/241205008/yamon-site/issues/7)）

- 編集：観察会詳細の情報カードの「編集」から、観察会名・場所・日付・時間を変更できる。紐づく記録の日付や場所は変わらない
- 削除：紐づく観察記録は削除せず、観察会との紐づけだけを外して「観察会なし」の記録として残す
- 操作できるのは、観察会を作った本人と管理者

### 主な場所

- 主な場所は固定のマスターではなく、**管理者（代表・副代表）**が画面から追加・編集するデータにする
- 座標は4県の範囲内に限る
- 記録がある場所は削除できない。使わなくなった場所は「使わない」状態にして、選択肢から外す（過去の記録の表示には残る）

### 地図

- 基本の地図は Protomaps（OpenStreetMap のデータ）を4県の範囲で切り出し、自分たちのストレージ（Cloudflare R2）から配信する
- 国土地理院の航空写真に切り替えて表示できる（出典を表示する）
- 地図は4県の外へ動かせない。範囲外の座標は API でも受け付けない
- **管理者が管理者画面の「地図データを更新」ボタンで、最新の地図データに入れ替えられる**

### データの削除

記録と生き物は、利用者が削除の操作をしない限り消えない。記録は記録した本人が削除すると完全に消える（ゴミ箱は設けない。2026-10-16 ユーザー決定）。

## 4. 個人情報の扱い

登録画面に次の内容を表示する。

- メールアドレスは、ログインのために使う（メールの設定がある環境では、招待・パスワード再設定のメールにも使う）
- 観察した日時と場所は、このサイトの一番大事な記録として保存する。見られるのは部員と OB・OG だけで、それ以外の人には公開しない
- 退会すると、名前とメールアドレスは削除される。観察記録はサークルの記録として残り、記録者は「退会済みユーザー」と表示される

## 5. メール・リンクの受け渡し

本人に渡すリンクは次の2種類。メールの設定（サークルの Gmail、代表が代々引き継ぐアカウント）は任意で、設定がなくても管理者画面のリンクで運用できる（2026-10-19 ユーザー決定、D46）。

- 招待リンク（48時間有効・1回限り）。管理者画面に出し、管理者が LINE などで渡す。メールの設定があればメールでも送る（D46）
- パスワード再設定リンク（1時間有効・1回限り）。管理者が管理者画面で発行して渡す。メールの設定があれば、本人がメールで申請もできる（D46）

## 6. データ

- ユーザー（名前・メールアドレス・役割・状態［通常／無効化／退会］）
- セッション（最大8時間）
- 招待（トークン・有効期限・使用済みか）
- パスワード再設定トークン（1時間）
- 操作履歴（役割の変更・無効化・退会処理を、誰がいつ行ったか）
- 生き物（名前・カテゴリ4種・メモ・位置を保護するか）。カテゴリはサークルの部門（インセクター／ママル／アクア／バーダー）で、今のまま使う
- 主な場所（名前・座標・使うかどうか）
- 観察会
- 観察記録（生き物・観察会・主な場所とは ID で紐づけ。座標と観察会はなくてもよい）
- 固定マスター：カテゴリ4種、役割
- 日時は日本時間で扱う
- バックアップ：毎日、データベースを丸ごと保存し、**3日分**残す

## 7. MVP に含まないもの

| 項目 | 扱い |
|---|---|
| 写真の添付 | 掲載の予定はない。将来、写真を保存することになった場合の保存先の候補だけ、事前に調べておく（Could） |
| オフラインでの記録と後からの同期 | 観察場所は基本的に電波が届く。できれば作る（Could）。地図を端末に保存してオフラインで表示することは、地図を自前で配信する構成なので後から足せる |
| 記録の外部提供（CSV 出力など） | 予定はないが検討はしたい。提供の範囲・同意・保護対象の生き物の扱いを調査する（[#26](https://github.com/241205008/yamon-site/issues/26)） |
| 記録のゴミ箱（削除の取り消し） | 作らない（2026-10-16 ユーザー決定） |
| localStorage 版の既存データの移行 | デモデータしかないため不要 |
