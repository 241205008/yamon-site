# MVP（合意版）

フロントエンド・バックエンド分離版の MVP。2026-10-13 にユーザーと合意し（[Issue #6](https://github.com/241205008/yamon-site/issues/6)）、2026-10-15 にサークルの責任者の回答を受けて更新した（[Issue #22](https://github.com/241205008/yamon-site/issues/22)）。
デザイン（Figma Make の7画面）と初期の仕様書 SPEC.md（リポジトリ外）を土台にし、食い違う場合はここに書いた内容を優先する。

## 1. 前提

- 自然観察会の参加者が、見つけた生き物を記録・共有する Web アプリ
- 運営は大学のサークルへ委託する予定。招待制。利用者は約100人（300人程度まで増えても無料で動く構成にする）。10年以上使い続ける
- 管理者は代表と副代表の2人体制
- バックエンドを作る目的は次の3つ
  - 端末やメンバーの間でデータを共有する
  - サーバー側で認証・権限を検証する
  - 容量を気にせず記録を貯め続ける
- 費用は無料枠の範囲に収める（サークルの予算の目安は年1,000円程度）
- スマホが主な利用環境（観察会の現場で記録する）。全画面をレスポンシブ対応にする
- 観察の範囲は東海3県（愛知・岐阜・三重）

## 2. 役割と権限

### 役割

| 役割 | 想定する人 |
|---|---|
| 管理者 | 代表・副代表。複数人を置ける |
| 幹部 | サークルの幹部 |
| 部員 | 一般の部員 |
| 閲覧のみ | 卒業生・OB・OG など。記録を見ることだけできる |

役割とできることの対応は1か所（`packages/shared`）で定義し、役割を後から足せるようにする。

### できること

| 操作 | 未ログイン | 閲覧のみ | 部員 | 幹部 | 管理者 |
|---|---|---|---|---|---|
| ログイン、招待リンクからの登録、パスワード再設定 | ○ | — | — | — | — |
| 記録・観察会・地図・場所別一覧を見る | × | ○ | ○ | ○ | ○ |
| 保護対象の生き物の正確な位置を見る（下記） | × | ×（ぼかした位置） | ×（ぼかした位置） | ○ | ○ |
| 記録を追加する | × | × | ○ | ○ | ○ |
| 記録を編集・削除する | × | ×（自分の過去の記録も不可） | 自分の記録のみ | 自分の記録のみ | 自分の記録のみ |
| 観察会を作る | × | × | ○ | ○ | ○ |
| 観察会を編集・削除する | × | × | 自分が作った観察会のみ | 自分が作った観察会のみ | ○（すべて） |
| 生き物を登録・編集・削除する（記録があるものは削除不可） | × | × | ○ | ○ | ○ |
| 生き物に「位置を保護する」印を付ける | × | × | × | ○ | ○ |
| 主な場所を追加・編集する | × | × | × | ○ | ○ |
| 招待、役割の変更、無効化、退会処理 | × | × | × | × | ○ |

権限はすべてサーバー側で検証する。画面でボタンを隠すだけにしない。

### 保護対象の生き物の位置

- 生き物ごとに「位置を保護する」印を付けられる（希少種などを想定）
- 印の付いた生き物の記録は、部員と閲覧のみの人には約1km単位に丸めた位置を返す。地図のピンもその位置に立つ
- 丸める処理は API 側で行い、正確な座標をブラウザに送らない

### 管理者

- 管理者は、他のユーザーの役割を「管理者／幹部／部員／閲覧のみ」に変更できる
- 最後の1人の管理者は、降格・無効化・退会させられない（管理者がいなくなるのを防ぐ）
- 役割の変更・無効化・退会処理は、誰がいつ行ったかを操作履歴に残す

### アカウントの状態

| 状態 | ログイン | 閲覧 | 記録の追加・編集 | 名前・メールアドレス | 元に戻せるか |
|---|---|---|---|---|---|
| 通常（管理者／幹部／部員） | ○ | ○ | ○ | 残す | — |
| 閲覧のみ（役割） | ○ | ○ | × | 残す（閲覧のみにするとき本人の同意を取る） | ○ 管理者が役割を戻せる |
| 無効化（一時停止） | × | × | × | 残す | ○ |
| 退会（匿名化） | × | × | × | 名前は「退会済みユーザー」、メールアドレスは削除 | × 戻せない |

- 典型的な流れ：部員 →（卒業）→ 閲覧のみ →（本人の希望など）→ 退会
- 退会してもその人の観察記録は残し、記録者は「退会済みユーザー」と表示する

## 3. 画面と機能

| 画面 | 機能 |
|---|---|
| 初回セットアップ | ユーザーが1人もいないときだけ表示。最初の管理者（名前・メールアドレス・パスワード）を登録する。登録には、デプロイした人だけが知っているセットアップ用トークン（サーバーの環境変数）の入力を必須にし、公開直後に第三者が管理者になるのを防ぐ（[#4](https://github.com/241205008/yamon-site/issues/4)） |
| ログイン `/login` | メールアドレス＋パスワードでログイン。招待メールのリンク（48時間有効・1回限り）から名前とパスワードを設定して登録。「パスワードを忘れた方」から再設定メールを受け取り、自分で再設定する（[#5](https://github.com/241205008/yamon-site/issues/5)） |
| ホーム `/` | 観察記録の追加・編集・削除（生き物の検索選択・その場での新規登録、場所＝主な場所／その他／指定しない、地図クリックや GPS での座標、日時、メモ）。最近の記録10件。観察会の作成（3ステップ）。生き物管理。閲覧のみの人には追加・編集の操作を出さない |
| マップ `/map` | 座標のある記録をピン表示し、同じ地点はまとめる。生き物・月・時間帯で絞り込み。地図は東海3県の範囲だけ表示し、国土地理院の航空写真に切り替えられる |
| 場所別 `/locations` | 主な場所ごとに、見られた生き物と観察回数 |
| 観察会一覧 `/event-list` | 統計と観察会の一覧 |
| 観察会詳細 `/event-detail/:id` | 観察会内の記録の追加・編集・削除。観察会の編集・削除（[#7](https://github.com/241205008/yamon-site/issues/7)） |
| 管理者 `/admin` | 招待メールの送信・再送・取り消し、役割の変更、無効化・有効化、退会処理、操作履歴、統計 |
| 主な場所の管理 | 管理者・幹部が主な場所を追加・編集する（管理者画面の中、または専用の画面） |

### 観察会の編集・削除（[#7](https://github.com/241205008/yamon-site/issues/7)）

- 編集：観察会詳細の情報カードの「編集」から、観察会名・場所・日付・時間を変更できる。紐づく記録の日付や場所は変わらない
- 削除：紐づく観察記録は削除せず、観察会との紐づけだけを外して「観察会なし」の記録として残す
- 操作できるのは、観察会を作った本人と管理者

### 主な場所

- 主な場所は固定のマスターではなく、管理者・幹部が画面から追加・編集するデータにする
- 座標は東海3県の範囲内に限る
- 記録がある場所は削除できない。使わなくなった場所は「使わない」状態にして、選択肢から外す（過去の記録の表示には残る）
- 初期データは、幹部が作る「よく行く場所」の一覧を入れる（受け取るまでは今の5か所を仮の値にする）

### 地図

- 基本の地図は Protomaps（OpenStreetMap のデータ）を東海3県の範囲で切り出し、自分たちのストレージ（Cloudflare R2）から配信する
- 国土地理院の航空写真に切り替えて表示できる（出典を表示する）
- 地図は東海3県の外へ動かせない。範囲外の座標は API でも受け付けない

## 4. メール

自動で送るメールは次の2種類。送信元はサークルの Gmail（代表が代々引き継ぐアカウント）。

- 招待メール（登録リンク、48時間有効）
- パスワード再設定メール（再設定リンク、有効期限つき・1回限り）

## 5. データ

- ユーザー（名前・メールアドレス・役割・状態［通常／無効化／退会］）
- 招待（トークン・有効期限・使用済みか）
- パスワード再設定トークン
- 操作履歴（役割の変更・無効化・退会処理を、誰がいつ行ったか）
- 生き物（名前・カテゴリ4種・メモ・位置を保護するか）
- 主な場所（名前・座標・使うかどうか）
- 観察会
- 観察記録（生き物・観察会・主な場所とは ID で紐づけ。座標と観察会はなくてもよい）
- 固定マスター：カテゴリ4種、役割
- 日時は日本時間で扱う

## 6. MVP に含まないもの

| 項目 | 理由 |
|---|---|
| 写真の添付 | ストレージの費用と容量の設計が必要。MVP 後に検討する |
| オフラインでの記録と後からの同期 | 実装量が大きい。電波の弱い場所での利用状況を見て判断する。地図を端末に保存してオフラインで表示することは、地図を自前で配信する構成なので後から足せる |
| 記録の外部提供（CSV 出力など） | 予定はないが検討はしたい（責任者の回答）。提供の範囲・同意・保護対象の生き物の扱いを調査する Issue を作る |
| localStorage 版の既存データの移行 | デモデータしかないため不要 |
